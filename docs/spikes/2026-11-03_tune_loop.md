# 스파이크: 사람 없이 도는 튜닝 루프 (근거 분석 → Claude 제안 → 검사 → GPU 측정 → 수집)

## 1. 가장 위험한 가정

**"층별 근거 분석만 받은 Claude(새 문맥, 도구 없음)가 라운드마다 검사를 통과하는 제안을 내고, 사람 개입 없이 루프가 끝까지 돌며,
시작점보다 나은 배정을 찾는다."**

- 맞으면: "AI 가 모델을 자동으로 최적화한다"를 사람 없이 재현할 수 있다.
- 틀리면 둘 중 하나다.
  - 제안이 검사(예산 · 근거 · 숫자)를 못 넘는다: 분석 형식이나 규칙 전달이 부족하다.
  - 측정에서 나아지지 않는다: 이 세션 바깥의 지식 없이는 개선을 찾지 못한다.
- 지휘 세션이 손으로 도는 루프([2026-11-03_tune_agent.md](./2026-11-03_tune_agent.md))와 다른 점은 다음과 같다.
  - 제안자가 라운드마다 새로 시작한다.
  - 제안자가 보는 것은 분석 JSON 뿐이다.
  - 제안 이후의 모든 단계가 코드로 돈다.

## 2. 시간 제한

2 라운드 × 제안 4개. 측정은 라운드당 약 20분(A100 1장). 제안 호출은 라운드당 비용 상한 2달러(`--max-budget-usd`).

## 3. 성공 조건 (실행 전에 확정)

**공통 설정**

- 세션 프로토콜은 `app/tune_agent.MEASURE_DEFAULTS`, 제안 엔진은 `claude-code` (기본 모델).

| # | 조건 | 판정 |

- 실행 도중 사람이 개입하면(제안 수정 · 재시작 · 측정 재시도) L1 은 실패로 적는다. 인프라 장애로 다시 시작한 경우에는 그 사실과 이유를 적는다.
- test PPL 은 루프 안에서 재지 않는다. 최선의 레시피는 루프가 끝난 뒤 1회만 잰다 (보조, 판정에 쓰지 않음).

## 6. 판단

**판정: 채택 (L1 · L2 통과).**
- 새 문맥으로 시작한 제안자가 분석 JSON 만으로 표 밖의 축(GPTQ 옵션)을 찾았다. 측정 이력에서 효과를 갈라냈다: act_order −0.0030, damp 0.005 −0.0007.
- 거부 사유를 되먹이는 경로가 작동했다 (통과 2/4 → 4/4).
- 지휘 세션의 수동 루프(에이전트 스파이크 A1)도 같은 방향(act_order · mse · damp 0.005)을 독립적으로 찾았다.

실행 뒤 반박 리뷰가 찾은 것 (판정은 바꾸지 않고 해석에 적는다):
- **제안자가 "분석 JSON 만" 본 것은 아니다.**
  - `--tools ""` 는 내장 도구만 끈다. 제안자는 repo 에서 돌았으므로 전역 · 프로젝트 `CLAUDE.md` (`AGENTS.md` 포함) 가 자동으로 로드됐다. 입력은 31,878 토큰으로, 프롬프트 약 3~4k 토큰을 크게 넘는다.
  - 이 파일들에는 지시와 용어집만 있고 측정값은 없다. TriCast 경로용 프로젝트 메모리는 존재하지 않았다.
  - 모델의 `analysis` 가 한국어로 온 것도 전역 지시 때문으로 보인다.
  - `3fc6907` 에서 격리를 바꿨다: 빈 디렉터리, MCP 없음, 설정 출처 없음. 같은 구조의 프로브 입력은 2,013 토큰이다.
- **클러스터 쪽 실행 래퍼(`run_round.sh`)를 코드가 만들지 않았다.**
  - 지휘 세션이 실행 전에 에이전트 세션의 래퍼를 복사해 두었다. 실행 도중에는 개입하지 않았다.
  - `3fc6907` 부터는 루프가 래퍼를 직접 쓴다.
- 결과 검사도 보강했다 (`3fc6907`): `kl.json` 이 요청한 레시피 · 세션 창 · 모델인지 확인하고, 원격 작업에 시간 제한을 둔다.

한계 (그대로 적는다):
- 제안자의 `analysis` 서술과 rationale 속 id 문자열은 검사하지 않는다. 숫자 가드는 rationale 의 소수만, 근거 검사는 `cites` 목록만 본다. 이번 최선 제안의 rationale 에는 존재하지 않는 id 문자열 하나가 섞여 있었다 ("E3993cc21a10 계열").
- 측정 2라운드 · 제안 8개 · 모델 1개 · 예산 1점이다. 개선은 검증 창 8개(4,096 토큰) KL 기준이다.
