## 1. 무엇을, 어떻게 읽는가 (측정 전에 정함)

### 1.1 모델과 실행 환경

- 모델: `Tongyi-MAI/Z-Image-Turbo` revision `f332072aa78be7aecdf3ee76d5c247082da564a6` (Apache-2.0). 6.15B 파라미터
  확산 트랜스포머(S3-DiT: 본 블록 30 · refiner 2+2, dim 3840), 텍스트 인코더 Qwen3 계열(hidden 2560, 36층), VAE 16채널.
  8번의 transformer 호출로 한 장을 만든다 (모델 카드의 8 NFE, guidance 0). diffusers 0.39 의 기본 시그마(linspace(1, 1/N, N))
  에서는 `num_inference_steps=8` 이 8번 호출이다 — 카드 예시의 9 는 이전 스케줄 기준이며, 9 로 두면 9번 호출되는 것을 refs 첫
  실행이 잡았다 (프롬프트 4개에 36번).
- 실행: UCL V100-PCIE-32GB (athens · london), `gpu_cap` 경유, 클러스터 conda `tricast` (torch 2.8.0+cu128,
  transformers 4.55.2) + diffusers 0.39.0 · Pillow 11.3.0 (별도 경로 `pydeps_diff`, 기존 환경은 그대로). HF 오프라인, seed 42.
- 정밀도: **FP32**. 체크포인트의 transformer 가 FP32 로 저장돼 있고, V100 시험(2026-11-14 05:10 UTC)에서 FP16 은 512 · 1024 px
  모두 latent 가 유한하지 않았다 (값 범위 초과). BF16 은 V100 에서 에뮬레이션뿐이다 (행렬곱이 돌기는 하나 매우 느림).
- 해상도 **512 px** (모델 기본은 1024 px). FP32 V100 에서 1024 px 의 비용이 표 측정에 맞지 않아 줄였다 — 한계로 남긴다 (§4).

### 1.2 무엇을 양자화하나

- transformer 의 Linear 276개 중 입력 폭이 128의 배수인 **275개** (6,153,617,408 파라미터, transformer 의 99.98%).
  입력 폭 64 의 패치 임베더 1개와 정규화 · 패딩 토큰 등은 원래 값 그대로 두고 크기에 16비트로 센다.
- 텍스트 인코더 · VAE 는 양자화하지 않고 크기에도 넣지 않는다 (화면의 "원본" = transformer 의 BF16 크기 12.3 GB).
- 체크포인트의 FP32 텐서 521개(6,154,908,736 값)는 **모두 BF16 값**이다 (BF16 로 바꿔 되돌려도 비트 단위로 같음, monaco CPU 에서
  전수 확인). 그래서 원본은 BF16 모델이고, FP32 계산은 그 가중치를 FP32 산술로 돌린 것이다. 로드할 때마다 다시 확인한다.
- 방법 (가중치만, fake-quant, 보정 없는 RTN): BF16 유지(= 원본 그대로, 16비트) · INT8 (출력 행마다 대칭, fp32 스케일) · INT4 ·
  INT3 · INT2 (입력 128개마다 fp16 스케일 + 정수 영점 — LLM 표의 GPTQ 방법과 같은 형식, 여기서는 RTN). 모든 방법은 (q − z)·s 를
  FP32 로 정확히 복원한다 (BF16 반올림 없음). 저장 비트: INT8 8 + 32/K, INTb b + (16 + b)/128.

### 1.3 셋업

| 구분 | 셋업 | 규칙 |
|---|---|---|
| 기존 방법 | INT8 / INT4 / INT3 균일 | 모든 층에 한 방법 |
| 기존 방법 | 흔한 규칙 | 임베더(t · caption) · adaLN 변조 · 마지막 층은 INT8, 나머지 INT4 (확산 트랜스포머 양자화에서 흔히 넓게 두는 층) |
| 우리 방법 | Auto-tune × 3 | 층별 표 위의 다중 선택 배낭을 정수계획(scipy milp · HiGHS, 상대 갭 0)으로 풀고, 비용은 정수로 다시 확인. 예산 = INT4 균일 · 흔한 규칙 · INT3 균일의 평균 비트와 정확히 같음 |

### 1.4 층별 표 (목적 함수)

- 표 프롬프트 4개 (제품 사진 · 붐비는 야경 · 글자 간판 · 인물, 시드 42+k). 각 프롬프트의 원본 생성에서 transformer 가 받은 입력
  8개를 기록하고 (`refs`), 층 하나만 양자화한 모델에 같은 입력 32개를 다시 넣는다.
- D = Σ‖v_q − v‖² / Σ‖v‖² (v = 원본의 출력 속도장, 같은 입력). 배낭은 층별 D 의 합을 최소화한다 (가산 가정 — 셋업 전체를
  양자화한 실측 D 를 함께 적어 가정을 확인한다).

### 1.5 평가와 판정

- 평가 프롬프트 24개 (표 프롬프트와 겹치지 않음, 시드 1042+k, 셋업마다 같은 초기 잡음). 각 셋업의 8단계 생성 결과를 원본
  모델의 같은 시드 이미지와 비교한다: **SSIM (주 지표, 11×11 가우시안 창)** · PSNR (dB). 원본과의 차이이지 품질 자체(사람
  평가 · CLIP 점수)가 아니다.
- 판정: Auto-tune 셋업마다, **그 크기를 정한 기존 셋업**(INT4 균일 · 흔한 규칙 · INT3 균일 — 측정 전에 정해진 짝)과
  프롬프트별 SSIM 차이로 짝 비교한다. 정확 sign-flip 검정(2^24 전수, 양측), 세 판정에 Holm 보정. 보정한 p < 0.05 이고 평균 차이
  > 0 이면 "우리 우세", < 0 이면 "기존 우세", 아니면 "차이 없음".
- 화면의 비교 막대 · 표는 같은 예산 안 기존 방법 가운데 가장 좋은 것과도 나란히 보인다 (결과를 보고 고르므로 기존 쪽에 유리 —
  판정에는 쓰지 않음). 예시 이미지 3장은 평가 프롬프트 24개 가운데 앞 3개이고, 판정 24개에 포함된다 (측정 전에 정함).

### 1.6 측정 전에 고친 것 (교차 검토, 2026-11-14 05:30 UTC)

Codex(읽기 전용)가 스크립트 · 화면 · 이 절을 반박 검토해 10건을 냈다. 표의 첫 행을 쓰기 전에 아래처럼 고치고, 이미 쓰인 두 행은
버렸다 (`zimage/w2/aborted_bf16_dequant/`).

| 지적 | 고침 |
|---|---|
| INT4 · 3 · 2 의 복원이 BF16 반올림을 거침 (`mma_input: dequant` 의 기본 `dequant_format`) — INT8 과 경로가 다름 | 모든 방법을 FP32 복원으로 명시, 테스트가 (q − z)·s 와 비트 단위로 대조 |
| "FP16 유지" 가 실제로는 FP32 원본 그대로인데 16비트 · 오차 0 으로 계산 | 원본이 BF16 값임을 전수 확인하고 "BF16 유지" 로 바꿈, 로드마다 확인 |
| 실제 크기(275층, 예산 2억 단위)에서 정확 DP 가 너무 큼 | 정수계획으로 풀고 비용을 정수로 다시 확인, 해의 하한(bound)과의 차를 기록 |
| 결과를 보고 고른 비교 상대로 p 값을 냄 (선택 편향) | 측정 전에 정한 짝(크기를 정한 셋업)으로 판정, Holm 보정 |
| 이어서 재기 · 합치기 · 평가 재사용이 다른 조건의 행을 섞을 수 있음 | refs 해시 · 정밀도 · 해상도 · 방법 명세 · 배치를 묶은 지문을 첫 행 전에 쓰고 모든 단계에서 대조 |
| D 의 제곱합이 FP32 에서 넘칠 수 있고, NaN 이 JSON 에 들어갈 수 있음 | FP64 로 합산 · 유한성 검사, `allow_nan=False`, 검증기가 모든 수치를 확인 |
| 내보낸 원본 항목에 지표가 없어 화면이 멈춤 · PSNR null(같은 이미지) 처리 · 검사 정규식 | 원본 지표 {SSIM 1, PSNR 없음}, null 을 "같은 이미지" 로 처리, 검사가 "기준 · 같음 · —" 를 받음 |
| 예시 3장을 판정에서 뺀다는 문장이 코드와 다름 | 판정 24개에 포함된다고 고침 (위) |

같은 엔진의 재검토(고친 부분만, 06:30 UTC)는 8건 해결 · 2건 부분 해결과 새 지적 3건을 냈고, 모두 표가 끝나기 전에 고쳤다: 평가 ·
내보내기도 지문을 다시 계산해 표와 대조 (이전에는 refs 해시만), 평균 SSIM · PSNR 이 NaN 이면 검증기가 거부 (`abs(NaN) > tol` 이
거짓이던 구멍), 짝 비교 통계를 프롬프트별 값으로 다시 계산해 대조, 검출 화면의 "지표가 모두 있어야 표를 보임" 규칙을 원래대로
(완화는 이미지 생성에만), 층 띠의 "BF16 유지" 표기.
