## 2. 맡긴 일과 성공 기준 (구현 전에 정함)

- **태스크**: `tricast.pack` (만들기 · 불러오기 · 실행), `yolo_tune.py onnx` (정수 가중치 ONNX + onnxruntime 평가),
  화면 ⑤ 연결 (`pack_index.py` → `packages.json` → `tune.js`), SPEC · ARCHITECTURE · README.
- **성공 기준**:
  1. 패키지의 모든 층을 풀면 TriCast 에뮬레이션이 곱하는 가중치와 비트 단위로 같다 — 다르면 패키지를 쓰지 않는다.
  2. 다시 불러 잰 WikiText-2 PPL 이 같은 GPU 의 TriCast PPL 과 0.1% 안이다.
  3. ONNX 는 정수 × 스케일이 내보낸 가중치와 비트 단위로 같고, onnxruntime 의 COCO mAP 가 PyTorch 기록과 같다.
  4. 화면 ⑤ 는 기록이 있는 셋업에만 실제 파일 정보를 보이고, 없으면 만드는 명령을 보인다.
  5. `ruff check` 무경고, CPU · 앱 · GPU 테스트 통과 (`linear.py` 를 바꾸므로 GPU 포함, AGENTS §6).
- **맡기지 않은 것**: 기존 테스트 · 골든 · evals 판정 기준의 변경, 커밋, 사람 라벨.

## 4. 검증에서 나온 결함과 처리

근거 문서 §5 (구현 중 찾은 6건)와 §6 (교차 검토 15건)에 있다. 이미 만든 결과에 영향이 있었던 것은 두 가지다.

- **ONNX IR 버전**: INT4 를 넣고도 IR 9 로 저장했다. onnxruntime 은 열었지만 규격(INT4 는 IR 10 부터)에 맞지 않아, 고친 코드로
  INT 셋업 4개를 다시 만들었다.
- **0 의 부호**: TriCast 는 작은 음수 가중치를 −0 으로 두는데 정수 코드에는 부호 있는 0 이 없다. "비트 단위로 같다" 는 문장을
  "0 의 부호를 빼고 같다" 로 고치고, 그 차이가 +0 에서 시작하는 합을 바꾸지 않는다는 것을 테스트로 남겼다.
