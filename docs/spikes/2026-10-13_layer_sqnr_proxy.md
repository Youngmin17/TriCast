> 2026-10-13 Quantizer 개편 중 돌린 스파이크다. **1~4절은 실험 뒤에 문서로 옮겨 적었다** — 판정 규칙(같은 예산의
> 무작위 선택과 비교)은 실험 전 지휘 세션의 W1 계획에 있었지만 파일로 남기지 않았다. 무작위 arm 은 처음 1개(seed 42)였고,
> 첫 결과를 받은 뒤 검토에서 "무작위 arm 이 하나라 분포가 없다"는 지적이 나와 seed 1~4 를 더했다. 결과를 본 뒤 추가한
> arm 이라는 점을 밝혀 둔다. 판정 규칙은 바꾸지 않았고, 처음 규칙(무작위 1개와 비교)으로도 결론은 같다 (5절).
> 실험 설계 · 실행 · 문서는 지휘 Claude Code 세션이 했고, 팀 추인은 아직 받지 않았다.

# 스파이크: 레이어 리포트의 국소 오차로 "지킬 레이어"를 고를 수 있는가

> 강의 4 지침의 여섯 절 구성을 따른다.

## 1. 가장 위험한 가정

**"레이어 리포트에서 국소 출력 SQNR 이 가장 낮은(가장 많이 망가진) Linear 를 원래 정밀도로 두면, 같은 개수를 무작위로
두는 것보다 모델 전체 품질(PPL)을 더 많이 회복한다."**

- 맞으면: 레이어 지도(`tricast report`)가 곧 "지킬 레이어 목록"이 되고, 자동 튜닝은 리포트 한 번으로 후보를 고를 수 있다.
- 틀리면: 레이어를 고르려면 모델 전체 지표(KL · PPL)를 후보마다 다시 재야 해서, 자동 튜닝의 비용과 설계가 달라진다.
- 인터뷰 근거: 로그 10 의 요약 "PC에서 한 민감도 분석이 칩에서 쓸모없음" 은 PC ↔ 폰(칩) 사이의 **환경 간** 순위 불일치다.
  이 스파이크는 그와 다른 종류 — 같은 환경 안에서 국소 지표 ↔ 모델 전체 효과 — 가 맞는지를 묻는다.
- 다른 후보와 비교: "격자가 레시피로 정확히 바뀐다"는 가정은 CPU 테스트로 싸게 확인된다 (SPEC AC15). 이 가정만 GPU 에서
  모델 전체 평가를 여러 번 돌려야 확인되고, 틀리면 제품 설계(자동 튜닝 목적 함수)가 바뀐다.

## 2. 시간 제한

GPU 반나절 (A100 1장 기준 PPL 1회 약 16~20분 × arm 7개 + 리포트 1회). 실측: 2026-10-13 하루 안에 끝남 (리포트 296.7초,
PPL 은 arm 당 약 20분).

## 3. 성공 조건

- 모델 · 형식: Qwen3-0.6B (revision `c1899de`), 번들 레시피 `mxfp4_w_a` (W · A MXFP4, 누산 프리셋 `nvidia_blackwell_fp4`)
- 예산: Linear 196개 중 **14개**를 BF16 로 둔다 (`skip: true`). 첫 · 마지막 블록(0 · 27)의 Linear 수와 같은 **개수** 예산이다 — 지키는 파라미터 비율은 arm 마다 다르다 (5절)
- arm
  - `top14` — 리포트의 출력 SQNR 이 가장 낮은 14개 (동률이면 이름 순)
  - `rand14` — `random.Random(seed).sample(sorted(196개 이름), 14)`, seed 42 (처음) + 1 · 2 · 3 · 4 (추가)
  - 참고 arm — 블록 0 · 27 (번들 레시피 `mixed_first_last_bf16`)
- **채택 조건**: `top14` 의 PPL 이 무작위 arm 보다 낮다. 무작위 5개가 생긴 뒤에는 "무작위 5개의 최솟값보다 낮다"를 확실한
  채택, "범위 안"을 구별 불가로 읽는다.

## 4. 방법 (성공 조건을 재는 데 필요한 것만)

| 단계 | 내용 |

| 리포트 | `tricast report --model Qwen/Qwen3-0.6B --recipe mxfp4_w_a` — WikiText-2 train 8 × 512 토큰, seed 42, Tesla V100-PCIE-16GB. Linear 196개 모두 측정 (`lm_head` 제외) |
| 선택 | `make_selection.py` 가 `report.json` (sha256 `29ff0b48e183…`) 에서 `top14` 와 `rand14` 를 골라 레시피를 쓴다. 기준 레시피 해시 `a40da150ce58…` |
| PPL | WikiText-2 test 전체 146 × 2048 창 (298,862 토큰, 데이터 지문 `a46124b21ac53738`), NVIDIA A100-SXM4-80GB |
| 코드 | TriCast `ab489f1` 의 수정 없는 클론 (`git_dirty: false`), torch 2.8.0+cu128 · transformers 4.55.2 |
| 결정론 | seed 42 · `CUBLAS_WORKSPACE_CONFIG` 설정. CLI 는 `torch.use_deterministic_algorithms(True)` 를 부르지 않는다 — 같은 트리에서 원본 PPL 20.9662 가 `support_matrix.yaml` 의 과거 기록과 같아 기준선은 흔들리지 않았다 |

## 5. 결과

| arm | BF16 로 둔 Linear | 그 Linear 의 파라미터 비율 | PPL | 원본과의 차이(12.97) 중 회수 |
|---|---|:-:|:-:|:-:|
| 원본 (BF16) | — | — | 20.9662 | — |
| MXFP4 전체 | 0개 | 0% | 33.9409 | 0% |
| 블록 0 · 27 (`mixed_first_last_bf16`) | 14개 | 7.1% | **29.6883** | **32.8%** |
| 무작위 seed 42 | 14개 | 7.38% | 32.1474 | 13.8% |
| 무작위 seed 1 · 2 · 3 · 4 | 14개씩 | 6.67% · 8.33% · 6.90% · 6.67% | 33.3784 · 32.6875 · 32.8613 · 31.8504 | 4.3% ~ 16.1% |
| 무작위 5개 평균 (범위) | | 7.19% | 32.58 (31.85 ~ 33.38) | 10.5% |
| `top14` (국소 SQNR 최저) | 14개 | **5.48%** | 33.1232 | 6.3% |

<sub>파라미터 비율 = 고른 Linear 의 파라미터 ÷ Linear 196개 전체 (레이어 종류마다 크기가 달라 같은 14개라도 다르다 — `v_proj` · `k_proj` 는 `gate` · `up` · `down` 의 ⅓). 원본과의 차이 = 33.9409 − 20.9662 = 12.9747. 회수 = (33.9409 − arm PPL) ÷ 12.9747.</sub>

- `top14` (33.12) 는 처음 조건인 무작위 seed 42 (32.15) 보다 **나쁘고**, 무작위 5개의 범위(31.85 ~ 33.38) 안에 있다.
- 블록 0 · 27 을 지키는 쪽은 무작위 5개 모두보다 좋다. 그런데 이 두 블록은 리포트에서 블록 평균 출력 SQNR 이 28개 블록 중 가장
  높았다 (블록 27 16.9 dB · 블록 0 16.8 dB, 전체 평균 16.24 dB — 덜 망가진 쪽). `top14` 의 14개에는 블록 0 · 27 의 Linear 가
  `v_proj` 1개(블록 27)뿐이다.
- `top14` 의 14개는 `v_proj` 8개 · `o_proj` 3개 · `up_proj` 3개로, 국소 오차는 레이어 **종류**(특히 `v_proj`)에 몰렸다.

## 6. 판단과 재도전 조건

**판정: 가정 기각 (미달) — 잠정** — 국소 출력 SQNR 로 고른 레이어는 무작위와 구별되지 않았다. 다만 `top14` 가 지킨 파라미터(5.48%)는 무작위
평균(7.19%)보다 약 24% 적어 이 비교는 `top14` 에 불리하다. 무작위 5개 안에서는 파라미터 비율과 PPL 사이에 뚜렷한 관계가 보이지 않았다
(비율이 같은 6.67% 의 두 arm 이 31.85 와 33.38). 이 교란은 판정 규칙을 정할 때 고려하지 않은 것이다 (절차 결함 2).

**재도전 조건** — 다음 중 하나가 생기면 같은 예산 · 같은 무작위 arm 5개로 다시 판정한다.

1. 국소 지표를 바꿀 때: 출력 SQNR 대신 레이어 하나만 양자화했을 때의 모델 logits KL (보정 데이터 8 × 512 토큰) — 국소가 아니라
   "그 레이어만 바꾼 모델 전체" 지표다. 비용은 레이어당 순전파 1회라 리포트 수준이다.
2. 다른 방법 · 모델로 넓힐 때: NVFP4 · Llama-3.2-1B 에서 같은 결과(구별 불가)가 나오면 일반화해 적는다.
3. 무작위 arm 은 처음부터 5개 이상 둔다 (이번 스파이크의 절차 결함 1).
4. 예산을 개수가 아니라 **파라미터 비율**로 맞춘다 — 같은 비율의 무작위 arm 과 비교 (절차 결함 2). 이 재판정 전까지 판정은 잠정이다.
