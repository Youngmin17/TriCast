## 1. 무엇을, 어떻게 읽는가 (측정 전에 정함)

### 1.1 모델과 실행 환경

- 모델: `Tongyi-MAI/Z-Image-Turbo` revision `f332072aa78be7aecdf3ee76d5c247082da564a6` (Apache-2.0). 6.15B 파라미터
  확산 트랜스포머(S3-DiT: 본 블록 30 · refiner 2+2, dim 3840), 텍스트 인코더 Qwen3 계열(hidden 2560, 36층), VAE 16채널.
  8번의 transformer 호출로 한 장을 만든다 (모델 카드의 8 NFE, guidance 0). diffusers 0.39 의 기본 시그마(linspace(1, 1/N, N))
  에서는 `num_inference_steps=8` 이 8번 호출이다 — 카드 예시의 9 는 이전 스케줄 기준이며, 9 로 두면 9번 호출되는 것을 refs 첫
  실행이 잡았다 (프롬프트 4개에 36번).
- 실행: UCL V100-PCIE-32GB (athens · london), `gpu_cap` 경유, 클러스터 conda `tricast` (torch 2.8.0+cu128,
  transformers 4.55.2) + diffusers 0.39.0 · Pillow 11.3.0 (별도 경로 `pydeps_diff`, 기존 환경은 그대로). HF 오프라인, seed 42.
- 정밀도: **FP32**. 체크포인트의 transformer 가 FP32 로 저장돼 있고, V100 시험(2026-11-14 05:10 UTC)에서 FP16 은 512 · 1024 px
  모두 latent 가 유한하지 않았다 (값 범위 초과). BF16 은 V100 에서 에뮬레이션뿐이다 (행렬곱이 돌기는 하나 매우 느림).
- 해상도 **512 px** (모델 기본은 1024 px). FP32 V100 에서 1024 px 의 비용이 표 측정에 맞지 않아 줄였다 — 한계로 남긴다 (§4).

### 1.2 무엇을 양자화하나

- transformer 의 Linear 276개 중 입력 폭이 128의 배수인 **275개** (6,153,617,408 파라미터, transformer 의 99.98%).
  입력 폭 64 의 패치 임베더 1개와 정규화 · 패딩 토큰 등은 원래 값 그대로 두고 크기에 16비트로 센다.
- 텍스트 인코더 · VAE 는 양자화하지 않고 크기에도 넣지 않는다 (화면의 "원본" = transformer 의 BF16 크기 12.3 GB).
- 체크포인트의 FP32 텐서 521개(6,154,908,736 값)는 **모두 BF16 값**이다 (BF16 로 바꿔 되돌려도 비트 단위로 같음, monaco CPU 에서
  전수 확인). 그래서 원본은 BF16 모델이고, FP32 계산은 그 가중치를 FP32 산술로 돌린 것이다. 로드할 때마다 다시 확인한다.
- 방법 (가중치만, fake-quant, 보정 없는 RTN): BF16 유지(= 원본 그대로, 16비트) · INT8 (출력 행마다 대칭, fp32 스케일) · INT4 ·
  INT3 · INT2 (입력 128개마다 fp16 스케일 + 정수 영점 — LLM 표의 GPTQ 방법과 같은 형식, 여기서는 RTN). 모든 방법은 (q − z)·s 를
  FP32 로 정확히 복원한다 (BF16 반올림 없음). 저장 비트: INT8 8 + 32/K, INTb b + (16 + b)/128.

### 1.3 셋업

| 구분 | 셋업 | 규칙 |
|---|---|---|
| 기존 방법 | INT8 / INT4 / INT3 균일 | 모든 층에 한 방법 |
| 기존 방법 | 흔한 규칙 | 임베더(t · caption) · adaLN 변조 · 마지막 층은 INT8, 나머지 INT4 (확산 트랜스포머 양자화에서 흔히 넓게 두는 층) |
| 우리 방법 | Auto-tune × 3 | 층별 표 위의 다중 선택 배낭을 정수계획(scipy milp · HiGHS, 상대 갭 0)으로 풀고, 비용은 정수로 다시 확인. 예산 = INT4 균일 · 흔한 규칙 · INT3 균일의 평균 비트와 정확히 같음 |

### 1.4 층별 표 (목적 함수)

- 표 프롬프트 4개 (제품 사진 · 붐비는 야경 · 글자 간판 · 인물, 시드 42+k). 각 프롬프트의 원본 생성에서 transformer 가 받은 입력
  8개를 기록하고 (`refs`), 층 하나만 양자화한 모델에 같은 입력 32개를 다시 넣는다.
- D = Σ‖v_q − v‖² / Σ‖v‖² (v = 원본의 출력 속도장, 같은 입력). 배낭은 층별 D 의 합을 최소화한다 (가산 가정 — 셋업 전체를
  양자화한 실측 D 를 함께 적어 가정을 확인한다).

### 1.5 평가와 판정

- 평가 프롬프트 24개 (표 프롬프트와 겹치지 않음, 시드 1042+k, 셋업마다 같은 초기 잡음). 각 셋업의 8단계 생성 결과를 원본
  모델의 같은 시드 이미지와 비교한다: **SSIM (주 지표, 11×11 가우시안 창)** · PSNR (dB). 원본과의 차이이지 품질 자체(사람
  평가 · CLIP 점수)가 아니다.
- 판정: Auto-tune 셋업마다, **그 크기를 정한 기존 셋업**(INT4 균일 · 흔한 규칙 · INT3 균일 — 측정 전에 정해진 짝)과
  프롬프트별 SSIM 차이로 짝 비교한다. 정확 sign-flip 검정(2^24 전수, 양측), 세 판정에 Holm 보정. 보정한 p < 0.05 이고 평균 차이
  > 0 이면 "우리 우세", < 0 이면 "기존 우세", 아니면 "차이 없음".
- 화면의 비교 막대 · 표는 같은 예산 안 기존 방법 가운데 가장 좋은 것과도 나란히 보인다 (결과를 보고 고르므로 기존 쪽에 유리 —
  판정에는 쓰지 않음). 예시 이미지 3장은 평가 프롬프트 24개 가운데 앞 3개이고, 판정 24개에 포함된다 (측정 전에 정함).

PSNR 평균 차이는 +0.51 · +0.95 · +0.88 dB (같은 순서, 판정에는 쓰지 않음). 판정은 "프롬프트별 차이가 0 을 중심으로 대칭" 이라는
귀무가설의 기각까지만 말한다. 화면 막대의 "기존 최선" 은 결과를 보고 고른 것이라 판정에 쓰지 않았다 (세 크기 모두 짝과 같은 셋업이 최선).

### 3.3 예측 D 와 실측 D

층별 D 의 합(배낭이 최소화한 값)은 셋업 전체를 양자화해 잰 D 보다 늘 크다 (실측 / 예측 = 0.28–0.80, 비트가 낮을수록 차이가 큼) —
§1.4 의 가산 가정은 값으로는 맞지 않는다. 다만 7개 셋업의 순서는 예측과 실측이 같다 (INT8 < Auto INT8/4 크기 < Auto INT4 크기 <
흔한 규칙 < INT4 < Auto INT3 크기 < INT3). 그리고 실측 D 의 순서는 SSIM 의 순서와도 같다.

### 3.4 Auto-tune 이 고른 것

- 26% (INT4 크기): INT8 38층 — adaLN 변조 10 · `to_v` 9 · `to_out` 7, 블록 15–22 에 몰림 (표에서 INT4 오차가 가장 큰 18–22 블록의
  `to_v`), `t_embedder` 2층. 대신 INT3 48층 · INT2 14층 (주로 `to_q` · `to_k` · `to_out`).
- 20% (INT3 크기): INT8 6층 (`t_embedder` 2 · `cap_embedder` · 마지막 층 2 · 블록 21 `to_v`), INT4 80층 (adaLN 25 포함), INT2 62층.

## 4. 한계 · 미검증

- **512 px · FP32** 에서만 쟀다 (모델 기본은 1024 px, 배포는 보통 BF16). 1024 px 로 결론이 옮겨지는지는 미검증이다.
- **기존 방법은 RTN 의 균일 배정과 흔한 규칙뿐**이다. 확산 모델용 보정 양자화(Q-Diffusion · SVDQuant 등)와 비교하지 않았다 — 그 방법들의
  공식 코드를 이 모델에 돌리지 않았다.
- 가중치만 양자화한 fake-quant 다. 활성값 양자화 · 저비트 커널 · 속도 · 모델 패키지는 없다.
- SSIM · PSNR 은 원본 이미지와의 차이이지 품질이 아니다 (사람 평가 · CLIP 점수 · FID 없음). 8단계 생성은 작은 가중치 오차에도 구도가
  바뀌어, INT8 균일(50%)도 SSIM 0.90 이다.
- 표 프롬프트 4개, 평가 프롬프트 24개 (프롬프트마다 시드 하나). 26% 는 차이 없음이다.
- 층별 오차가 비트 순서를 어긴 층이 하나 있다: `noise_refiner.0.adaLN_modulation.0` 에서 INT3 (1.13e-4) < INT4 (1.37e-4). 그룹 영점의
  RTN 에서 생길 수 있는 일이고, 그대로 표에 두었다.
- 측정은 V100 한 종류, 해석과 수용 판단은 한 사람(위임 기록 §5)이다.
- §5 의 두 크기(19% · 16%)는 첫 결과를 본 뒤 더한 시연용 크기다. 판정 규칙은 그 셋업들을 재기 전에 정했지만, "기존이 무너지는 크기"를
  고른 것 자체가 결과를 본 선택이다. 같은 비트 수끼리의 비교가 아니라 그 크기 안에서 고를 수 있는 것끼리의 비교다 (기존 = 13% 의 INT2 균일).

## 5. 추가 — 계단 사이 크기 (첫 결과를 본 뒤 더함, 이 절은 측정 전에 씀 · 2026-11-14 13:36 UTC)

### 5.1 왜, 무엇을, 어떻게 판정하나

- **왜**: §3 의 세 크기에서는 기존 방법(INT4 · INT3 균일, 흔한 규칙)도 알아볼 수 있는 이미지를 만들어, 화면에서 기존과 우리의
  차이가 잘 보이지 않는다 (사람 지적, 2026-11-14). Qwen3-8B 의 시연 셋업(2026-11-13)처럼 **한 방법의 비트 계단 사이 크기**를 더한다:
  INT3 균일(3.1484 비트, 19.7%)보다 조금이라도 작아야 하면 기존 방법은 INT2 균일로 내려가야 한다. 이 크기를 더한 것은 §3 의 결과를
  본 뒤이고, 그래서 아래 판정은 이 셋업들을 재기 전에 정한 규칙으로만 낸다.
- **셋업**: INT2 균일 (`u_int2`, 2.1406 비트, 13.4%) · Auto-tune 예산 평균 3 비트 (`auto_b300`, 18.8%) · 2.5 비트 (`auto_b250`, 15.6%).
  예산은 표의 예측 D 를 3 · 2.75 · 2.5 비트에서 계산해 본 뒤 3 과 2.5 를 골랐다 (실측은 보지 않음).
- **짝**: 두 예산 안에 드는 기존 방법은 INT2 균일 하나뿐이다 (INT3 균일 · INT4 균일 · 흔한 규칙은 예산을 넘는다).
- **판정**: §1.5 와 같은 규칙 — 프롬프트 24개의 SSIM 짝 차이, 정확 sign-flip (2^24, 양측). Holm 보정은 **이 두 크기 안에서만** 한다.
  §3.2 의 세 판정은 측정 전에 정한 가족 그대로 두고, 가족을 합쳐 다시 보정하지 않는다.
- **같은 기록 위에서**: refs · 표 · 실행 지문은 그대로다. 배낭은 새 코드로 다시 풀고, §3 의 세 해가 같은 배정으로 나오는지 확인한다
  (처음 해는 `solutions_first.json` 으로 남긴다).
- **예측 (표, 측정 전)**: INT2 균일 D 1.699 · Auto 3 비트 0.2615 (INT8 3 · INT4 72 · INT3 122 · INT2 78층) · Auto 2.5 비트 0.5864
  (3 · 17 · 99 · 156층). 가설: INT2 균일은 원본과 다른 이미지가 되고 (SSIM 이 INT3 균일 0.588 보다 크게 낮음), Auto 3 비트는 INT3 균일
  수준(SSIM ≥ 0.55)을 지킨다. 가설이 틀리면 그대로 적는다.
