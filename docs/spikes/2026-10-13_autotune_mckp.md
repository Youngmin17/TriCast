# 스파이크: 층 하나만 줄인 모델의 KL 로 층마다 비트를 고르면, 같은 크기의 사람 · 균일 레시피보다 나은가 (Auto-tune v1)

> 강의 4 지침의 여섯 절 구성을 따른다.

## 1. 가장 위험한 가정

**"층 하나만 양자화한 모델의 출력 차이(KL)를 층 × 방법마다 재서 더하면 여러 층을 함께 줄였을 때의 손실을 순서대로 예측할 수
있고, 그 합을 크기 예산 안에서 최소화한 배정이 같은 크기의 균일 · 사람 레시피보다 모델 전체 품질(PPL)이 좋다."**

- 맞으면: Auto-tune 은 층 × 방법 표 한 번(모델 전체 평가 수천 회가 아니라 짧은 순전파 수천 회)과 배낭 문제 풀이로 끝난다.
- 틀리면: 층 사이 상호작용 때문에 합이 실제 손실을 예측하지 못하는 것이고, 반복 탐색(조합을 실제로 재며 고치기)이 필요해 비용이 커진다.
- 근거: W1 스파이크([2026-10-13_layer_sqnr_proxy.md](./2026-10-13_layer_sqnr_proxy.md))에서 층의 **국소** 출력 SQNR 은 모델 전체 효과를
  예측하지 못했다 (잠정). 그 문서의 재도전 조건 1 이 "그 층만 바꾼 모델 전체" 지표다 — 이 스파이크가 그것을 목적 함수로 쓴다.
- 인터뷰 근거: P3 (레이어별 혼합 정밀도를 손으로 전수 탐색 — 09 10 11 12 13 14), P9 (원하던 조합의 일부만 평가 — 07).

## 2. 시간 제한

1일 (지휘 세션 작업 + GPU A100 1~2장). 층 × 방법 표 측정은 1시간 안, PPL 평가는 레시피당 약 16~18분 (W2 실측 914~1,070초).
종료 조건은 3절의 조건을 모두 잰 시점 또는 1일 경과 중 먼저 오는 쪽.

## 3. 성공 조건 (실험 전에 확정)

공통 조건: Qwen3-0.6B (revision `c1899de`), Linear 196개, 수정 없는 트리의 커밋에서 실행, seed 42.
방법 후보는 보정이 필요 없는 7가지 — `bf16` · `nvfp4` · `nvint4` · `mxfp4` · `mxfp8` · `int8` · `bfp12` (Quantizer 방법 카탈로그,
`mma_input: dequant`). 크기는 `app/export_quantizer_demo.py` 의 `WEIGHT_BITS` 로 센 Linear 가중치 평균 비트 (계산값).

| # | 조건 | 판정 |
|:-:|---|---|
| C1 | 배정 풀이가 작은 문제(층 ≤ 8, 방법 7)에서 완전 탐색의 최적값과 같다 (이산화 오차 한도 안) | CPU 테스트 |
| C2 | 예측(층별 KL 의 합)과 실측(레시피 전체를 적용한 모델의 KL, 표를 잰 데이터와 **다른** 창)의 Spearman 순위 상관 ≥ **0.8** — 보정 없는 레시피 10개 이상 (균일 프리셋 4 · 무작위 격자 · Auto-tune 결과) | GPU 측정 |
| C3 | 크기 **4.50 비트** (균일 NVFP4 와 같음) 에서 Auto-tune 레시피의 WikiText-2 test PPL **< 26.16** (`qd_nvfp4`) | GPU 측정 |
| C4 | 크기 **5.72 비트** (`qd_mixed` 와 같음, KV 는 같은 KIVI-2 `fakequant`) 에서 PPL **≤ 25.98** (`qd_mixed` — 보정 방법 AWQ · GPTQ 를 쓰는 사람의 레시피) | GPU 측정 |

- **채택**: C1 · C2 · C3 모두 통과. C4 는 보정 방법이 없는 v1 에게 불리한 비교라 통과하면 "사람 레시피 수준", 실패하면 "보정 방법을
  후보에 넣는 v2 가 필요"로 읽는다 (가설 기각이 아님).
- **기각**: C3 실패 — 같은 크기의 균일 배정보다 낫지 않으면 이 방식(층별 KL 합 + 배낭 풀이)은 v1 으로 쓸 가치가 없다. C2 실패는 "합으로
  예측 안 됨"으로 기록하고, C3 이 통과해도 근거가 약하다고 적는다.
- 보조로 잴 것 (판정에 쓰지 않음): 크기 4.25 (균일 MXFP4) · 5.09 (`qd_mxfp4_ends_bf16`) 지점의 PPL, 표 측정 시간.

## 4. 방법 (성공 조건을 재는 데 필요한 것만)

1. **층 × 방법 표**: 보정용 WikiText-2 train 창 (8 × 512 토큰, seed 42) 에서 원본 logits 를 한 번 잰 뒤, 층 하나 · 방법 하나만 적용한
   레시피 (Quantizer 생성기로 만든 것과 같은 명세) 로 순전파해 원본 대비 다음 토큰 분포 KL 평균을 잰다. 196 × 6 = 1,176회 (BF16 은 0).
2. **배정 풀이**: 다중 선택 배낭 — Σ KL(층, 방법) 최소화, Σ 파라미터 × 비트 ≤ 예산. 정수 DP (비트 해상도를 정해 이산화), 작은 문제는
   완전 탐색과 대조 (C1).
3. **레시피**: 풀이 결과를 Quantizer 격자(블록 × 종류)로 바꿔 `app.quantizer_recipe.build` 로 YAML 을 만든다 — 화면에서 열리는 것과
   같은 레시피다.
4. **C2**: 표와 다른 창 (WikiText-2 train, seed 43 의 8 × 512 토큰) 에서 레시피 전체 KL 을 잰다.
5. **C3 · C4**: `tricast run` 의 PPL (WikiText-2 test 전체, 146 × 2048 창) — W2 와 같은 설정 · 같은 GPU 종류 (A100).

### 4절 보충 — 구현 뒤 · GPU 측정 전에 정한 것 (2026-10-13, 결과를 보기 전)

구현(`app/autotune.py`)을 끝낸 뒤 측정 전에 다음을 정했다. 성공 조건(3절)은 그대로다.

- 크기 5.09 지점은 `qd_mxfp4_ends_bf16` 의 정확한 크기 **5.0892857 비트**로 둔다 (5.09 는 0.0007 비트 크다).
- 크기 4.25 에서는 배정이 균일 MXFP4 하나뿐이라 `auto_4.25` = `qd_mxfp4` 다 — C2 에서 중복으로 세지 않는다.
- C2 레시피 (서로 다른 11개): 균일 4 (`qd_nvfp4` · `qd_nvint4` · `qd_mxfp4` · `qd_mxfp4_ends_bf16`) · 무작위 격자 4 (seed 1~4, 층마다
  7방법 중 균등 — 크기 약 7비트라 같은 크기 비교가 아니라 순위 범위를 넓히는 용도) · Auto-tune 3 (4.50 · 5.0892857 · 5.72 KV 없음).
- 표에는 KV 오차가 없으므로 C2 에는 KV 없는 `auto_5.72` 를, C4 PPL 에는 같은 배정에 KIVI-2 `fakequant` 를 넣은 `auto_5.72_kivi2` 를 쓴다.
- 발화 · 동치 증거: 표를 잰 뒤 한 층짜리 격자를 표와 같은 창(seed 42)에서 `measure` 로 다시 재서 표 값과 같은지 본다.
