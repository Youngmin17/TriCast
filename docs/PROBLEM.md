## 1. 한 문장 문제 ✍️

저정밀 연산기(텐서코어·NPU MAC 어레이)를 설계하는 하드웨어 설계자·연구자가, 수 형식·양자화·누산기 구조
후보가 LLM 품질에 주는 영향을 설계 단계에서 **믿을 수 있게, 빠르게** 확인하지 못해, 대리 지표(랜덤 행렬
오차)로 결정하거나 설정 하나마다 재빌드와 수십 분~수 시간의 평가 왕복을 치른다. *(가설 — 인터뷰로 검증 전)*

## 2. 대상과 비대상 ✍️

- 1차 사용자: 연산기 RTL·마이크로아키텍처 설계자, 수 형식·양자화 방식을 설계하는 연구자
- 비대상(현재): 서빙 처리량을 최적화하는 엔지니어, 대규모 학습(QAT) 실무자, 일반 LLM 사용자

## 3. 증거

- 누산 구성 하나를 바꿔 LLM 품질을 보는 기존 공개 절차는 설정당 약 50분(36개 설정 약 30시간), 허용 값 밖의
  파라미터는 C++ 재빌드가 필요하다 (관찰 A1)
- 널리 쓰이는 MX 양자화 도구는 형식은 다루지만 누산 산술은 PyTorch matmul 에 맡긴다 (관찰 A2)
- 사용자 페인(대리 지표 의존, 왕복 비용): **로그 확보 후 작성** ✍️ (로그 __, __)

## 4. 반증 조건 ✍️

- 문제의 실재 (인터뷰 증거로 지금 판정)
  - 주장: 대상 사용자는 정밀도·누산기 결정을 LLM 수준 평가 없이 내리거나, 그 확인에 큰 왕복 비용을 치른다.
  - 반증 조건: 대상 10명 중 최근 6개월 안에 (a) LLM 품질 확인 없이 대리 지표만으로 결정했거나 (b) LLM 품질
    확인에 하루 이상 걸린 사례가 **3명 미만**이면 문제 정의를 기각하고 대상이나 문제를 다시 쓴다.
- 해결 가설 (제품 사용 관찰로 이후 판정)
  - 가설: 레시피 하나로 비트 정확 에뮬레이션과 LLM 품질 수치를 함께 돌려주면 결정 왕복이 줄어든다.
  - 반증 조건: 검증된(AC1·AC7 통과) 에뮬레이션 결과를 받고도 설계자가 같은 수치를 별도 C 모델이나 RTL
    시뮬레이션으로 다시 확인하는 행동이 계속 관찰되면 기각. 에뮬레이션이 실리콘·레퍼런스와 달라서 재확인한
    경우는 가설이 아니라 정확성(AC1) 문제로 따로 센다.

## 5. 성공의 정의 (행동 지표) ✍️

- 설계 결정 문서에서 근거로 TriCast 평가 기록(EvalRun)이 인용된 비율
